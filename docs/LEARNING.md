# DevLab 长期学习路线

## 学习方式

每课遵循「原理 → 最小实验 → DevLab 实际应用 → 技术笔记 → 测试验证」。对熟悉的前端能力保持适度投入，把主要精力放在 Node.js 和后端工程；实际应用按当前课题确定范围，基础实验可先联系已有代码分析。

以下功能是候选实践，不是当前实施清单。阶段内先完成一个可验证的功能，再按需求扩展；不为了覆盖技术名词提前引入基础设施。

## 模块笔记规范

课程笔记按主题目录组织，例如 `docs/01-nodejs/02-event-loop.md`；每个技术模块维护一篇。已有 `docs/notes` 中的初始化笔记保留，阶段进度位于 `docs/00-roadmap/progress.md`。

个人理解、问题回答与总结由学习者填写，助手只提供模板、实验说明和客观验证记录。

每篇包含：

1. **学习目标与真实场景**：要解决的用户问题，以及该技术为什么适合。
2. **核心原理**：机制、请求或数据流、关键概念、适用范围和限制。
3. **实现与取舍**：相关源码链接、接口或数据契约、关键步骤、方案选择原因。
4. **测试与实验**：可复现的命令、前置条件、预期结果、实际结果；涉及并发/缓存/事务时包含相应边界与失败场景。
5. **面试问题与回答要点**：结合本项目解释原理、权衡与排障过程。
6. **复盘与后续问题**：仍不理解的部分、实际限制和未来改进，明确区分计划与已完成内容。

更新功能后同步修正受影响笔记。阶段完成后更新本路线中的状态，避免把候选功能写成已实现能力。
