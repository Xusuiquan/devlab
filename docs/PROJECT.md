# DevLab 项目背景

## 开发者背景与目标

- 8 年前端开发经验，熟悉 React、TypeScript、Ant Design。
- 正在向 Node.js 全栈工程师转型，通过真实项目理解经典后端技术实现。
- 将可运行功能、技术原理、实验结果和面试问题沉淀到同一项目中，长期迭代。

## 产品定位

DevLab 是开发者知识库 + 技术实验平台。知识库用于管理后端学习笔记；技术实验围绕知识库的实际需求展开，例如权限、缓存、任务处理和语义检索。

目标是能解释为什么这样设计、有哪些边界、如何验证和排查，而不仅是完成接口或接入依赖。

## 架构

| 层次 | 选型 | 当前状态 |
| --- | --- | --- |
| 仓库管理 | pnpm workspace Monorepo | 已初始化 |
| 前端 | React + TypeScript + Vite + Ant Design | 最小欢迎页 |
| 后端 | NestJS + TypeScript | 最小应用及健康检查 |
| 数据库 | PostgreSQL + Prisma | 后续阶段 |
| 认证与授权 | JWT + RBAC | 后续阶段 |
| 缓存 | Redis | 后续阶段 |
| 异步任务 | BullMQ | 后续阶段 |
| 交付与运行 | Docker、CI/CD、测试与监控 | 后续阶段 |
| AI 应用 | AI RAG | 后续阶段 |

两个应用拥有独立依赖与构建配置，根工作区统一调度。目前没有稳定的共享代码需求，因此不创建共享包，也不引入额外 Monorepo 编排工具。

## 当前阶段：项目初始化

已提供：

- `apps/web`、`apps/api`、`docs` 目录和 pnpm workspace。
- 前后端开发、类型检查、构建和后端构建产物启动命令。
- `GET /api/health`，仅表示 API 进程能够响应，不检查外部服务。
- Vite 开发代理，前端通过同源 `/api` 访问后端。
- `AGENTS.md`、项目背景、学习路线和初始化技术笔记。

尚未实现知识库业务、数据持久化、注册登录、权限、缓存、队列、容器化或 AI 能力。欢迎页不是知识库功能的交付。

## 迭代原则

1. 每学习一种新技术，就为 DevLab 增加一个真实功能。
2. 按当前阶段引入依赖，以真实需求推动技术升级。
3. 优先理解技术原理，再选择适当的库，通过实验验证其工作机制。
4. 保持代码简单、规范、模块化，遵循根目录 `AGENTS.md` 的最小 Diff 约定。
5. 每个技术模块都有 Markdown 笔记，涵盖原理、实现、测试和面试问题。

阶段规划与笔记规范见 [LEARNING.md](LEARNING.md)，环境和启动命令见 [README](../README.md)。后续需求明确改变范围或阶段时，同步更新本文件。
